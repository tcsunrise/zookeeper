# zk-quiz：ZooKeeper 源码每日 Quiz

用户每天阅读本仓库 ZooKeeper 3.3.6 源码（分支 dev-3.3.6）和相关文章，之后把学习内容发过来。本 skill 有两种模式：**出题**（默认）和**批改**。

所有输出（题目、说明、批改）使用简体中文；类名、方法名、字段名保持英文原样。

---

## 模式一：出题

### 1. 提取主题
从用户消息（或 `/zk-quiz` 的参数）中提取：
- 当天学习主题（一句话）
- 涉及的类 / 方法 / 字段 / 配置项 / 概念
- 用户的理解要点、疑问点（疑问点优先出成题）

如果用户没有提供任何学习内容，先问一句"今天学了什么？"，不要凭空出题。

### 2. 对照源码取证
- 用 Grep/Glob/Read 在 `src/java/main/org/apache/zookeeper/` 下定位相关代码（服务端主要在 `server/`、`server/quorum/`、`server/persistence/`，客户端在 `ClientCnxn.java`、`ZooKeeper.java`）。
- 可参考 `notes/` 下已有笔记和 `conf/` 下配置示例，了解用户此前学到哪里。
- 查阅 `docs/` 下 3.3.6 官方文档（优先读 `.html`，不读同名 `.pdf`），用于核对概念、配置项和设计说明。常用对应关系：
  - 内部原理、ZAB、选举、一致性保证 → `zookeeperInternals.html`
  - 数据模型、会话、Watch、ACL、一致性语义 → `zookeeperProgrammers.html`
  - 配置项、运维、四字命令、数据文件 → `zookeeperAdmin.html`
  - Observer → `zookeeperObservers.html`；分层 Quorum → `zookeeperHierarchicalQuorums.html`
  - 典型应用（锁、队列、选主等）→ `recipes.html`；整体概览 → `zookeeperOver.html`
  - 忽略 `bookkeeper*` 文档，除非用户当天学的就是 BookKeeper。
- **每道题都必须能在本仓库 3.3.6 源码或 `docs/` 文档中找到依据**；文档与源码表述冲突时以源码为准，可借此出一道辨析题。不要出 3.3.6 中不存在的特性（如 3.4+ 的 `multi`、3.5+ 的动态重配置 / Netty / Container 节点 / TTL 节点 等），除非题目明确是"对比后续版本"的设计思考题，并注明。
- 引用的类名、方法名、字段名必须是 Grep 确认存在的，不得臆造。

### 3. 生成 10 道题
题型与数量分布（可按内容微调，总数固定 10）：

| 题型 | 数量 | 说明 |
|------|------|------|
| 概念理解 | 2 | 是什么、为什么存在 |
| 流程梳理 | 2–3 | 调用链、执行顺序、线程交互 |
| 源码定位 | 2 | 指出负责某行为的类/方法/关键字段 |
| 场景分析 | 2 | "如果……会怎样"、异常/边界/宕机场景 |
| 设计思考 | 1–2 | 取舍、对比、可改进之处 |

要求：
- 难度由浅入深，用 ★ / ★★ / ★★★ 标注；大致 3 道 ★、4 道 ★★、3 道 ★★★。
- 题目紧扣用户当天内容，可以适当关联用户之前学过的模块（来自 `notes/` 或用户提及），但不超过 2 道。
- 题干要具体，避免"请简述 ZooKeeper"之类泛泛的问题。
- 可附"提示"指向具体文件/方法，但提示不能直接泄露答案。
- **文件中不写答案**，答案在批改时给出。

### 4. 写入文件
- 目录：`quiz/<yyyyMM>/`（如 `quiz/202610/`），按当天日期确定，不存在则创建。
- 文件名：`<yyyyMMdd>-<topic-slug>.txt`，日期不带分隔符，topic-slug 为英文小写短横线短名，如 `20261008-sync-request-processor.txt`。
- 同名文件已存在时追加 `-2`、`-3`……，**绝不覆盖已有文件**。
- UTF-8 编码，使用以下模板：

```
ZooKeeper 源码学习 Quiz
日期：<yyyy-MM-dd>
主题：<主题>
学习内容摘要：<2–3 行概括用户提供的内容>
涉及源码：<类名列表，逗号分隔>
==================================================

第 1 题 [概念理解] ★
<题干>
提示：<可选，没有则省略此行>

【我的答案】



--------------------------------------------------

第 2 题 [流程梳理] ★★
...

（共 10 题，最后一题后不加分隔线）
```

### 5. 回复用户
- 给出文件路径（`quiz/<yyyyMM>/<file>.txt`）。
- 列出 10 道题的一行简述（题号 + 题型 + 难度 + 简短标题），不剧透答案。
- 提醒作答后可说"批改"。

---

## 模式二：批改

用户说"批改""检查我的答案""对答案"等时触发。

1. 确定文件：用户指定的文件；未指定则取 `quiz/` 下修改时间最新的 txt。
2. 读取每题的【我的答案】。未作答的题标记为"未作答"，仍给出参考答案。
3. 逐题对照源码（及 `docs/` 文档、`notes/` 笔记）判断，必要时 Read 相关代码或文档确认，不凭记忆下结论。
4. 在文件**末尾追加**批改区块，**不修改用户已写的任何内容**：

```

==================== 批改 ====================
批改日期：<yyyy-MM-dd>
总分：<得分>/100（每题 10 分）

第 1 题：<得分>/10 —— <正确/部分正确/错误/未作答>
点评：<针对用户答案的具体点评，指出遗漏或错误>
参考答案：<要点式参考答案，引用 类名#方法名 或 docs/xxx.html 章节>

第 2 题：...

总结：
- 掌握较好：<…>
- 需要加强：<…>
- 建议复习：<具体类/方法>
```

5. 回复中给出总分和"需要加强"的要点即可，详细内容在文件里。
